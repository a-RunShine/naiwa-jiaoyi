# Java 后端与无独立管理后台

> 状态：✅ 与 [`../tech-stack.md`](../tech-stack.md) 同步更新（2026-09-09）
> 修订点：细化 JDK / 构建工具 / ORM / 图片存储四个决策

## 决策

期末不限技术栈，团队熟悉 Java。后端采用 **Spring Boot 4 + JDK 21 LTS + Gradle 8 (Groovy DSL) + MyBatis-Plus + MySQL 8**，后端与小程序分离。管理能力暂不做独立后台，通过数据库直操完成下架与异常订单处理，已在数据模型预留 `role` 与状态字段，未来可零成本补齐后台页面。

## 关键细化（相对原版）

### 后端框架与工具链

- **Spring Boot 4 + JDK 21 LTS**：Spring Boot 4 是当前主流，最低要求 JDK 17，JDK 21 LTS 提供虚拟线程作为未来性能 buffer
- **Gradle 8.x + Groovy DSL（`build.gradle`）**：不引入 Kotlin DSL
- **MyBatis-Plus 3.5.9+**：相比 plan.md 原 MyBatis，减少 CRUD 样板（`BaseMapper` + `QueryWrapper`），单表 CRUD / 筛选 / 分页开箱即用；接受 Spring Boot 4 暂无官方背书的风险
- **MySQL 8.0.x LTS**：支持 CHECK 约束（钱包 `balance >= 0` / `frozen <= balance`）
- **JJWT + 自写 JwtInterceptor，不引入 Spring Security**：JWT 自管签发 / 校验，砍掉 60% 依赖体积

### 图片存储

- **方案**：**微信云存储**（个人云开发免费配额 5GB，演示场景零成本）
- **落地**：保留 `POST /api/files/upload` 接口，**后端转发到微信云存储**，换取 HTTPS URL 落库
- **接口契约不变**：plan.md 既定的图片模块接口与字段全部保留，仅实现细节切换
- **为什么不用通用对象存储**：自建 MinIO / 阿里 OSS / 腾讯 COS 都需要额外服务或账号，演示网络一变图就加载不出；微信托管零运维
- **未来迁移**：接口抽象留好，后期可零成本切换到 MinIO / OSS / COS

### 鉴权

- **JWT + `wx.login` code2Session，开发期 Mock 登录**
- 真实微信登录需 AppSecret 且个人小程序受限，Mock 保障任何网络可演示
- 演示时登录页"演示账号"按钮一键选小白 / 小红 / 小黑，跳过 wx.login 直接拿 Mock JWT

### 管理后台

- 暂不实现页面，预留 `role` 与状态字段
- 治理走 DB 直操（dev 同学手动 SQL）
- 未来补齐后台页面只需新增 Controller，不动数据模型

## 被否决备选

- **Node.js / 云开发**：需额外学习且校内资料少
- **本地文件系统存图片**：plan.md 原否决理由依然成立（部署迁移成本高且小程序外网访问受限）
- **Spring Security**：plan.md 8 个模块接口数量有限，自写拦截器完全够用；Spring Security 配置复杂，引入是杀鸡用牛刀

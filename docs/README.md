## 🛠 文档维护规则

### 修改流程

1. **改 spec.md**：影响所有下游文档，需走 `/grilling` 重新对齐
2. **改 plan.md 接口契约**：必须同步更新 spec.md 的 F1-F10 与 AC1-AC14（否则验收标准失真）
3. **改 tech-stack.md**：必须同步更新 plan.md 的"技术决策表"行、ADR-0004 的对应小节、scaffold-tasks.md 的版本号
4. **新增 ADR**：按 `000N-中文标题.md` 命名，序号递增
5. **改 ADR**：不要改文件名（保持决策的不可变性），在文件末尾追加 "修订历史"

### 冲突解决优先级

当多份文档矛盾时，按下表权威性优先：

| 优先级 | 文档 | 理由 |
|--------|------|------|
| 🥇 | `tech-stack.md` | 决策层权威 |
| 🥈 | `adr/` | 单项决策的详细论证 |
| 🥉 | `plan.md` | 执行层；选型理由以 tech-stack.md 为准 |
| 4 | `spec.md` | 验收层；不写实现细节 |
| 5 | `scaffold-tasks.md` | 操作层；依赖前 4 份 |

### 变更后必跑的一致性检查

- [ ] plan.md 的"技术决策表"与 tech-stack.md §一是否一致
- [ ] plan.md 的"接口表"是否覆盖 spec.md F1-F10
- [ ] 所有文档的术语是否与 CONTEXT.md 一致（无 Avoid 词）
- [ ] 版本号是否在 tech-stack.md §四点五 锁定
